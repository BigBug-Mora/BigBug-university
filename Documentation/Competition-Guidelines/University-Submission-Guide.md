# University submission guide

Source [AI Catalyst 2026 University Submission Guidelines](AI_Catalyst_2026_University_Submission_Guidelines.pdf), pp. 2–7. See also the [University Track brief](University-Track-Brief.md) for the judging rubric and human baseline requirement.

| --- | --- |
| Proposal, maximum 10 pages | Friday, 20 November 2026 at 11:59 p.m. Late proposals earn no proposal marks. |

| Phase 2 feature development, for the 10 university finalists | Features released Monday, 7 December 2026 at 8:00 a.m. Submit before the competition ends using the same repository. |

## Required repository layout

```text
BigBug-university/
├── project/
│   ├── main.py
│   └── requirements.txt
├── README.md
├── docs/
│   ├── Proposal.docx
│   ├── Workflow.md
│   └── PROJECT_DETAILS.md
└── project-demo.mp4
```

Keep internal team material in the existing `Documentation/` directory. Keep organizer-facing submission documents in `docs/`. The guidelines allow supporting files and folders.

## Submission checklist

- [ ] Use a dedicated GitHub repository named in the `team_name-university` format. Grant the designated Innodata GitHub account member access, include the repository URL in the proposal, and keep the repository current and accessible to organizers.
- [ ] Write `docs/Proposal.docx` with the problem, affected users, urgency, research and global impact, proposed solution, objectives, features, and expected outcomes. Cover agent roles, coordination, decisions, human oversight, implementation, tools, dependencies, baseline, metrics, test scenarios, limitations, and ethics.
- [ ] Put the runnable entry point in `project/main.py`, dependencies in `project/requirements.txt`, and the overview, setup and run instructions in `README.md`.
- [ ] Document process flow and implementation in `docs/Workflow.md`. Document objectives, features, technical details and disclosures in `docs/PROJECT_DETAILS.md`.
- [ ] Submit the end-to-end Phase 1 prototype, source, input and output samples, and updated documentation. Finalists update the same repository with the Phase 2 implementation and evidence.
- [ ] Record `project-demo.mp4` covering the problem, solution, key functionality and an actual run. Use H.264 video and AAC audio, at least 720p (1080p preferred), and a duration of 5–10 minutes. The recommended size is 50–100 MB, with a 100 MB maximum.
- [ ] For the finale, prepare at most 10 slides and cover the problem, architecture, tools, benchmark evidence, feature integration, and scalability. The allocation is 5 minutes for setup, 15 minutes for the demo, and 10 minutes for Q&A. Overruns incur deductions.

## Competition rules

Build original work during the event. Use third-party components only as their licenses permit and acknowledge them. Declare every AI model, service, tool and coding assistant used in `docs/PROJECT_DETAILS.md`. Report results generated by the submitted solution and preserve their integrity. Keep credentials out of Git, use authorized data, protect Innodata-provided materials and delete them after the event. Compete fairly, follow applicable rules and policies, and respect organizer and judge decisions.
